# S-AES 加解密系统 · 用户指南

## 1. 项目简介

本项目是信息安全导论课程作业，实现了 **S-AES（Simplified AES，16 位分组 / 16 位密钥）** 算法及课程要求的全部五关扩展功能：

| 关卡 | 内容 | 对应模块 |
|---|---|---|
| 第 1 关 | 基本测试：16bit 明文 + 16bit 密钥 → 16bit 密文，GUI 支持加解密交互 | `gui.py` / `cli.py` |
| 第 2 关 | 交叉测试：与其他小组程序在异构平台比对加解密结果 | `cli.py vectors` |
| 第 3 关 | 扩展功能：ASCII 字符串分组加解密（每分组 2 字节，密文可能是乱码） | `gui.py` / `cli.py` |
| 第 4 关 | 多重加密：双重加密（32 位密钥）、中间相遇攻击、三重加密（EDE 32 位 / EEE 48 位） | `gui.py` / `cli.py` |
| 第 5 关 | 工作模式：CBC 模式加密较长消息（16 位 IV 生成与共享），篡改密文前后解密对比 | `gui.py` / `cli.py` |

## 2. 环境要求

- Python 3.9 及以上（本项目在 Python 3.13 下开发测试）
- GUI 需要 Streamlit：`pip install streamlit`
- 命令行与测试脚本无需任何第三方依赖

## 3. 快速开始

```bash
# 3.1 运行通关测试（无依赖，一键验证五个关卡，44 项测试）
python run_tests.py

# 3.2 启动图形界面（第 1 关要求的 GUI 交互）
streamlit run gui.py
# 浏览器自动打开 http://localhost:8501

# 3.3 命令行加密示例
python cli.py encrypt -k 1010011100111011 -p 0110111101101011
# 输出：密文 C : 0000000001100111 (0067)

# 3.4 查看标准交叉测试向量（第 2 关比对用）
python cli.py vectors
```

> 提示：若系统中有多个 Python，请统一使用同一个（例如 `py -3.13`）。

## 4. 图形界面（GUI）使用说明

运行 `streamlit run gui.py` 后，页面含 5 个标签页：

### 第1关 基本测试
- 输入 16 位密钥与 16 位明文（支持二进制 `1010...` 或十六进制 `a73b` / `0xa73b`）。
- 点击 **🔒 加密**：显示 16 位密文及每一步中间状态（轮密钥加、S 盒替换、行移位、列混淆）。
- 点击 **🔓 解密**：输入密文还原明文，同样展示解密中间过程。
- 默认填入标准测试向量：K=1010011100111011，P=0110111101101011 → C=0000000001100111。

### 第2关 交叉测试
- 展示标准测试向量表（相同 P、K 必得相同 C），可拖动滑块随机生成更多向量。
- 将本表发送给其他小组比对即可完成交叉测试。

### 第3关 ASCII 串
- 左侧输入任意明文字符串（含中文），点击加密得到**乱码密文字符串**。
- 复制密文字符串到右侧，点击解密还原原文。
- 说明：密文以 latin-1 字符呈现，每个字节对应一个字符，可无损复制还原。

### 第4关 多重加密
- **双重加密**：输入 32 位密钥（K1‖K2）进行加/解密。
- **中间相遇攻击**：填入已知明密文对（默认提供演示数据），一键攻击恢复 32 位密钥并显示耗时。候选多于 1 组时按提示再补一组明密文对即可。
- **三重加密**：左侧为 32 位密钥 EDE 模式，右侧为 48 位密钥 EEE 模式，均支持加解密。

### 第5关 CBC 工作模式
- **① 加密**：输入 16 位密钥与较长的明文消息（支持中文），IV 留空则随机生成；输出 IV 与密文分组（4 位十六进制）。IV 需与密文一并共享给解密方。
- **② 解密**：填入相同的密钥、IV 与密文分组，还原明文。IV 错误则无法还原（体现 IV 必须共享）。
- **③ 篡改对比**：指定要篡改的密文分组下标（或填入替换值），一键对比篡改前后的解密结果——被篡改组整体乱码、其下一组对应位翻转，其余分组不受影响。

GUI 各界面运行截图见 [docs/screenshots](screenshots)。

## 5. 命令行（CLI）完整用法

```text
python cli.py encrypt  -k <16位密钥> -p <16位明文>   [--fmt hex] [--trace]
python cli.py decrypt  -k <16位密钥> -c <16位密文>   [--fmt hex] [--trace]
python cli.py encrypt-ascii  -k <16位密钥> -t "明文字符串"
python cli.py decrypt-ascii  -k <16位密钥> -t "密文字符串"
python cli.py double-encrypt -k <32位密钥> -p <16位明文>
python cli.py double-decrypt -k <32位密钥> -c <16位密文>
python cli.py triple-encrypt -k <密钥> -p <16位明文> [--mode ede|eee]
python cli.py triple-decrypt -k <密钥> -c <16位密文> [--mode ede|eee]
python cli.py mitm -p <明文1> -c <密文1> [-p2 <明文2> -c2 <密文2> ...]
python cli.py cbc-encrypt -k <16位密钥> -t "较长明文..." [--iv <16位IV>]
python cli.py cbc-decrypt -k <16位密钥> --iv <16位IV> -t "<密文分组>"
python cli.py cbc-tamper  -k <16位密钥> -t "较长明文..." [-i <分组下标>] [--iv <IV>] [--value <替换值>]
python cli.py vectors
```

- `--fmt bin`（默认）接受二进制串，`--fmt hex` 接受十六进制；均可含空格或 `0x` 前缀。
- `--trace` 打印加密/解密每步中间状态，便于与其他小组逐步比对定位差异。
- `triple --mode ede` 使用 32 位密钥（K1‖K2，EDE 模式）；`--mode eee` 使用 48 位密钥（K1‖K2‖K3，EEE 模式）。
- `cbc-*` 为第 5 关 CBC 命令，`--iv` 为 16 位初始向量（16 位二进制或 4 位十六进制），省略则随机生成；密文分组为空格分隔的 4 位十六进制。

### 中间相遇攻击示例（第 4.2 关）

```bash
python cli.py mitm -p 0110111101101011 -c 1000000110010011 \
                   -p2 1011101101010001 -c2 0000100101010100
```

输出：

```text
已知明密文对 2 组，开始中间相遇攻击 ...
攻击耗时 3.000 秒，找到 2 组候选密钥：
  K1=0010110101010101 (2d55), K2=0000111100011110 (0f1e) -> 32位密钥 00101101010101010000111100011110
  ...
提示：候选密钥多于 1 组，请增加更多明密文对（第二/第三组）以唯一确定密钥。
```

> 原理提示：单组明密文对期望约有 2^16 个误匹配候选；每增加一组明密文对，误匹配约按 2^16 倍速缩减；三组即可唯一确定密钥（见开发手册 §5.2）。

### CBC 工作模式示例（第 5 关）

```bash
# 加密（IV 随机生成，输出 IV 与密文分组，需一并共享给解密方）
python cli.py cbc-encrypt -k 2d55 --fmt hex -t "S-AES CBC mode works on longer messages!"

# 解密（使用加密方共享的 IV 与密文分组）
python cli.py cbc-decrypt -k 2d55 --fmt hex --iv 1234 -t "bb15 0262 ... f237"

# 篡改实验：修改第 1 组密文，对比篡改前后的解密结果
python cli.py cbc-tamper -k 2d55 --fmt hex --iv 1234 -i 1 -t "S-AES CBC mode works on longer messages!"
```

篡改实验输出（节选）：

```text
原密文分组    : bb15 0262 f88f 9c47 ...
篡改后密文分组: bb15 fd9d f88f 9c47 ... （第 1 组被修改）
篡改前解密    : 532d 4145 5320 4342 ...
篡改后解密    : 532d 2b94 acdf 4342 ...
受影响明文分组: [1, 2]（共 21 组） → 第 1 组整体乱码；第 2 组对应位翻转；其余分组不变
```

## 7. 常见问题（FAQ）

**Q1：ASCII 解密后出现乱码或 `�` 字符？**
密钥错误或密文被损坏时会输出乱码（解密本身就是对随机数据的合法变换）。请核对密钥与密文是否完整复制（长度必须为偶数）。

**Q2：中间相遇攻击找到多个候选密钥？**
这是正常现象：单组明密文对约产生 2^16 个误匹配。多提供一至两组明密文对即可唯一确定。

**Q3：`streamlit` 命令找不到？**
用 `python -m streamlit run gui.py` 代替，并确认已 `pip install streamlit`。

**Q4：与其他小组结果不一致？**
先用 `python cli.py encrypt --trace` 对比每一步中间状态：①密钥扩展 K1/K2 是否一致 → ②初始轮密钥加 → ③S 盒查表 → ④行移位（交换第 2 行）→ ⑤列混淆（矩阵 [1 4; 4 1]）。差异通常出在这五处之一的规格理解上。

**Q5：CBC 解密用错 IV 会怎样？**
第一个明文分组首先出错，其后各组因链接关系相继出错（错误传播），整体无法还原。这正是 IV 必须由双方共享的原因。

**Q6：篡改密文后为什么只有相邻两组明文变化？**
CBC 的固有特性：篡改第 *i* 组密文，会使明文第 *i* 组整体乱码、第 *i+1* 组对应位翻转，其余分组不受影响；篡改末组则会破坏 PKCS#7 填充。

# S-AES 加解密系统 · 开发手册

本文档面向开发者与验收教师，给出算法规格、实现结构、关键设计、测试方案与已知结论。

## 1. 算法概述

S-AES（Simplified AES）是 Musa、Schaefer、Wedig 于 2003 年提出的面向教学的简化 AES 算法：

- **分组长度**：16 bit（2 字节，4 个半字节 nibble）
- **密钥长度**：16 bit，扩展出 3 把 16 bit 轮密钥（对应 2 轮结构）
- **数学基础**：GF(2⁴) 有限域，模不可约多项式 x⁴ + x + 1（0b10011）

## 2. 算法规格（本实现所遵循的标准）

### 2.1 状态矩阵与半字节排序

16 位输入按顺序切分为 4 个半字节 n0 n1 n2 n3（n0 为最高 4 位），**按列**填入 2×2 状态矩阵：

```text
┌ n0 n2 ┐
└ n1 n3 ┘
```

即第一列 (n0, n1) 是高 8 位字节，第二列 (n2, n3) 是低 8 位字节。**本实现与所有遵循该标准的教材/课程一致；若交叉测试不一致，请最先核对此处填充顺序。**

### 2.2 S 盒与逆 S 盒

S 盒（行 = 输入高 2 位 x，列 = 输入低 2 位 y）：

| x\y | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| **0** | 9 | 4 | A | B |
| **1** | D | 1 | 8 | 5 |
| **2** | 6 | 2 | 0 | 3 |
| **3** | C | E | F | 7 |

逆 S 盒为 S 盒的functional inverse（`INV_SBOX[SBOX[i]] == i`，已由单元测试 16 项全覆盖验证）：

| x\y | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| **0** | A | 5 | 9 | B |
| **1** | 1 | 7 | 8 | F |
| **2** | 6 | 0 | 2 | 3 |
| **3** | C | 4 | D | E |

> 说明：本表已经过数学自洽性验证——S 盒可由 GF(2⁴) 乘法逆元 + 仿射变换构造复现：
> 仿射映射 c=(1001)，列向量 col(a0)=1101, col(a1)=1011, col(a2)=0111, col(a3)=1110，
> 即 b = c ⊕ Σ col(ai)。用该映射与手工计算的 16 个逆元能完整重建上表（见 run_tests 单元自检思路）。

### 2.3 行移位 ShiftRows（NibbleShift）

仅交换状态**第二行**的两个半字节：n1 ↔ n3。逆变换与正变换相同（对合运算）。

### 2.4 列混淆 MixColumns

每列 (s0, s1) 左乘矩阵（GF(2⁴) 上运算）：

```text
┌ s0' ┐   ┌ 1 4 ┐ ┌ s0 ┐
└ s1' ┘ = └ 4 1 ┘ └ s1 ┘
```

即 s0' = s0 ⊕ (4·s1)，s1' = (4·s0) ⊕ s1。逆矩阵为 `[[9, 2], [2, 9]]`
（推导：det = 1 ⊕ 4·4 = 1 ⊕ 3 = 2，2⁻¹ = 9，adj = [1 4; 4 1]，得逆 = 9·[1 4; 4 1] = [9 2; 2 9]）。
测试已验证全部 65536 个状态满足 InvMix(Mix(x)) = x。

GF(2⁴) 乘法抽查值（均经手工推演并在测试中固化）：4·9=2，2·9=1，4·4=3，9·9=D，3·E=1，4·D=1。

### 2.5 轮密钥加 AddRoundKey

16 位状态与 16 位轮密钥逐位异或。

### 2.6 密钥扩展

16 位密钥拆为两个字 w0（高 8 位）、w1（低 8 位）：

```text
RotNib(w) = 交换 w 的高、低半字节
w2 = w0 ⊕ Rcon1 ⊕ RotNib(w1)     Rcon1 = 0x80 (1000 0000)
w3 = w2 ⊕ w1
w4 = w2 ⊕ Rcon2 ⊕ RotNib(w3)     Rcon2 = 0x30 (0011 0000)
w5 = w4 ⊕ w3

轮密钥：K0 = w0‖w1，K1 = w2‖w3，K2 = w4‖w5
```

手工推演示例（K = 0xA73B）：w2 = A7 ⊕ 80 ⊕ B3 = 94，w3 = 94 ⊕ 3B = AF，
w4 = 94 ⊕ 30 ⊕ FA = 5E，w5 = 5E ⊕ AF = F1，即 K1 = 0x94AF、K2 = 0x5EF1（测试已固化）。

### 2.7 加密 / 解密流程

```text
加密：                                解密（逆序）：
  AddRoundKey(K0)                       AddRoundKey(K2)
  ┌ NibbleSub                           ┌ InvShiftRows
  │ ShiftRows                           │ InvNibbleSub
  │ MixColumns          第 1 轮          │ AddRoundKey(K1)
  │ AddRoundKey(K1)                     │ InvMixColumns
  └ NibbleSub                           └ InvShiftRows
    ShiftRows                             InvNibbleSub
    AddRoundKey(K2)      第 2 轮(无列混淆)   AddRoundKey(K0)
```

## 3. 代码结构

```text
saes.py            单文件核心模块，零第三方依赖
├── 常量区         SBOX / INV_SBOX / RCON1 / RCON2 / 混淆矩阵
├── gf_mul()       GF(2⁴) 乘法（x⁴+x+1 模）
├── gf_inv()       GF(2⁴) 逆元（暴力枚举，仅用于测试/演示）
├── parse_bits() 等  二进制/十六进制解析与格式化
├── key_expansion()      16bit → (K0, K1, K2)
├── encrypt()/decrypt()  基本加解密，可选 trace 中间状态
├── encrypt_ascii()/decrypt_ascii()    第 3 关
├── double_encrypt()/double_decrypt()  第 4.1 关
├── meet_in_the_middle()               第 4.2 关
├── triple_encrypt_ede()/..._eee() 等  第 4.3 关
├── generate_iv() / cbc_encrypt() / cbc_decrypt()   第 5 关（CBC 工作模式）
├── cbc_error_propagation() / tamper_block()        第 5 关（篡改对比实验）
└── __main__ 自检    标准向量断言

cli.py       argparse 子命令 CLI（encrypt/decrypt/…/cbc-*/vectors）
gui.py       Streamlit 五标签页 GUI（含第 5 关 CBC 工作模式）
run_tests.py 五关卡 44 项测试
```

关键实现取舍：

1. **状态用 16 位整数而非 2×2 数组**：`_shift_rows`、`_mix_columns` 内部按位拆装半字节，逻辑与矩阵定义一一对应，便于对照规格核查。
2. **trace 模式**：`encrypt(..., trace=True)` 返回每步 (名称， 状态)，用于 GUI 展示与交叉测试排错。
3. **纯 Python 实现**：单次加密约几十微秒，MITM 全空间扫描（2×65536 次）约 1.5 s，满足教学演示；未做查表优化（必要性与收益低）。

## 4. 各功能设计

### 4.1 ASCII 串加密（第 3 关）

- 明文 `str → UTF-8 字节流`，按 2 字节分组，**PKCS#7 填充**（填充值 = 填充长度 1 或 2）。
- 每组 16 bit 走标准 S-AES 加密，密文字节流以 **latin-1** 解码为字符串输出（字节↔字符一一对应，可无损复制）。
- 解密：latin-1 编码还原字节流 → 逐组解密 → 去 PKCS#7 填充 → UTF-8 解码。
- 填充非法（错误密钥/密文损坏）时不抛异常，原样输出乱码，更符合"输出很可能是乱码"的题意。

### 4.2 双重加密（第 4.1 关）

`C = E_K2(E_K1(P))`，密钥 32 位 = K1(高 16 位) ‖ K2(低 16 位)。解密为逆序：`P = D_K1(D_K2(C))`。

### 4.3 中间相遇攻击（第 4.2 关）

攻击目标：给定同一 32 位密钥 (K1, K2) 的明密文对，恢复密钥。

```text
正向表：对每个 K1 ∈ [0, 2¹⁶) 计算 M = E_K1(P)，按中间值 M 建哈希表
反向匹配：对每个 K2 ∈ [0, 2¹⁶) 计算 M = D_K2(C)，命中即得候选 (K1, K2)
过滤：其余明密文对逐一验证候选，剔除误匹配
```

复杂度约 2¹⁶ + 2¹⁶ = 2¹⁷ 次加解密、O(2¹⁶) 空间，对比暴力搜索 2³² 有 2¹⁵ 倍加速。

**候选数量理论**：对固定密钥，E、D 均为双射，候选数期望 = 2¹⁶·2¹⁶/2¹⁶ = 2¹⁶（单对）；
每增加一组对，误匹配期望除以 2¹⁶：单组 ≈ 65536 个 → 两组 ≈ 1 个（Poisson(1)，仍可能 2~3 个）→
三组 ≈ 2⁻¹⁶（实际必唯一）。实测：单对 65490 个候选、两对缩减至 2 个、三对唯一恢复（见测试报告）。

### 4.4 三重加密（第 4.3 关）

| 方案 | 密钥 | 加密 | 解密 |
|---|---|---|---|
| EDE（类比 2 密钥 3DES） | 32 位 K1‖K2 | C = E_K1(D_K2(E_K1(P))) | P = D_K1(E_K2(D_K1(C))) |
| EEE | 48 位 K1‖K2‖K3 | C = E_K3(E_K2(E_K1(P))) | P = D_K1(D_K2(D_K3(C))) |

两种方案均已实现（作业只要求二选一），EDE 中间用解密函数使得"加密即解密"的互操作场景（如兼容旧单重加密硬件）成为可能。

### 4.5 工作模式 CBC（第 5 关）

CBC（Cipher Block Chaining，密码分组链接）用于加密较长的消息，16 位分组逐组链接：

```text
加密：C_i = E_K(P_i ⊕ C_{i-1})，C_{-1} = IV
解密：P_i = D_K(C_i) ⊕ C_{i-1}
```

设计要点：

1. **IV（初始向量，16 位）**：由 `generate_iv()` 使用 `secrets.randbelow(2^16)` 随机生成；加解密双方必须共享同一 IV，否则解密结果不正确（本关强调这一点）。为便于复现与演示，接口也允许显式传入 IV。
2. **分组与填充**：明文按 UTF-8 编码后以 2 字节为一组，末组不足时用 PKCS#7 填充（与第 3 关一致），因此 40 字节明文产生 21 组密文。
3. **链接依赖**：`cbc_decrypt(..., unpad=False)` 可返回未去填充的原始字节，便于篡改实验时做逐组对比。
4. **篡改实验**：`cbc_error_propagation()` 加密 → 篡改第 *i* 组密文（`tamper_block()` 按位取反或替换为新值）→ 再次解密，返回篡改前后的明文分组与受影响分组下标。

**错误传播特性（本关结论）**：篡改第 *i* 组密文后——

- 明文第 *i* 组：整体乱码（雪崩效应，`D_K` 对随机输入输出不可预测）；
- 明文第 *i+1* 组：与篡改位一一对应地翻转（因为 `P_{i+1} = D_K(C_{i+1}) ⊕ C_i'`，仅异或项改变）；
- 其余分组：完全不受影响；
- 若篡改的是**末组**，则 PKCS#7 填充被破坏，接收方解密时可检出填充错误。

该特性说明 CBC 具备一定的篡改可见性（无法无声地定向篡改某一分组），但可预测的第 *i+1* 组位翻转也提示：若需完整完整性保护，应叠加 MAC。

### 5.2 结果

- 标准向量 E(0x6F6B, 0xA73B) = 0x0067 ✓

## 6. 已知限制与说明

1. S-AES 本身为教学算法，16 位密钥不具备实际安全性（MITM 演示即说明这一点）。
2. `decrypt_ascii` 对错误密钥返回乱码而非报错（设计取舍，见 4.1）；UTF-8 解码失败处用替换字符呈现。
3. 中间相遇攻击对"两组明密文对"在极小概率下仍可能剩 2~3 个候选（Poisson(1) 分布），界面已给出提示，补第三组即可唯一确定。
4. GUI 默认端口 8501，可用 `--server.port` 修改；GUI 依赖 streamlit，CLI 与测试脚本零依赖。
5. CBC 模式下 IV 若被重复使用或未共享，会削弱安全性/导致解密失败；本次为教学演示，未叠加 MAC，篡改仅靠 CBC 传播特性与填充校验被发现。
